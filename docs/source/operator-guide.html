Rewards are paid manually in USDC on Base to the user's wallet address. The app promises payment within 48 hours of claiming.

2. What the user sees


The home-page banner advertises the challenges. "Get started" opens sign-up / deposit.

Users open the Account button (top right) — the "Your Rewards" section shows one swipeable card per challenge. The cards move through these states:


1 · In progress — live progress and a call to action ("Place a bet", "Deposit", "Verify now").

2 · Completed — "Completed" turns green and a Claim reward button appears. Clicking it adds a row to the claims sheet.

3 · Claimed — "Claimed — paid within 48 hours". The user now waits for you.

4 · Paid — after you add the address to payouts.json: "Reward received ✓" with a "View transaction" link; the chip shows $30 / $30.

Not eligible — accounts created before 24 Aug 2026 see the $5 card greyed out with a note. The $25 card is open to everyone.

3. Daily routine (do this once a day)

1
Open the claims sheet — claims sheet
Each row is one claim: Received At | Address | Challenge | Claimed At. Work through the rows that are not yet marked as paid (add a column E "Paid" and put the date there when done).
2
Pay — send $5 (kyc-deposit) or $25 (volume-700) in USDC on Base to the address in column B. Copy the transaction hash / Basescan link.
3
Record the payout in GitHub — open payouts.json (edit) and add one line under the matching challenge: 
"0xca7d70aF5076FA55705F3285e3414620f157948C": { "txHash": "https://basescan.org/tx/0x…", "paidAt": "2026-08-31" }

The GitHub editor for payouts.json — add the line, then "Commit changes…" (top right).
Rules: paste the address as copied (any casing); separate entries with commas — no comma after the last entry in a block; txHash can be the bare hash or the full Basescan link; update updatedAt at the top. Then click Commit changes… → Commit directly to the main branch → Commit.
4
Check the green tick — on the repo page, the commit gets a ✔ within a minute if the file is valid. A ✘ means a typo (usually a missing/extra comma or quote): open the file again, fix, commit again. The app ignores an invalid file, so nobody goes green until it's fixed.
5
Mark the sheet row as paid (date in column E). Done — the user's card turns green automatically within ~5–10 minutes (the file is cached for 5 minutes; the app re-reads it when the account modal opens).

  "challenges": {

      "0x2222222222222222222222222222222222222222": { "txHash": "0xbbbb…", "paidAt": "2026-08-27" }
    },

  }
}

4. Troubleshooting

SituationWhat to do
User says "I was paid but my card is still not green"Check the address is in payouts.json under the right challenge, the commit has a green ✔, and 10 minutes have passed. Ask them to reload the page and reopen Account.
Commit shows a red ✘The file is invalid. Common causes: comma after the last entry, missing quote, wrong challenge name (only kyc-deposit and volume-700 exist), address not 42 characters. Fix and commit again.
Same address claims twiceThe sheet ignores duplicate address + challenge pairs, so you'll only ever see one row per reward. Never pay twice.
"I can't edit the file on GitHub"Only the 8 allow-listed org members can commit to main. Ask an admin to add you to the branch-protection push list (repo → Settings → Branches → main).
User is old but was paid anywayA recorded payout always shows as paid, even for accounts outside the promo window — nothing to fix.
